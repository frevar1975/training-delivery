# Lab 15 - Share Team Knowledge using Azure Project Wiki

## Objetivo

Utilizar Azure Project Wiki para documentar y compartir conocimiento dentro de un equipo DevOps.

## Relación con el módulo

Module 08 - Implement Continuous Feedback

## Conceptos relacionados

- Knowledge Sharing
- Documentation
- Azure DevOps Wiki
- Markdown
- Collaboration
- Team Practices

## Escenario

Un equipo necesita centralizar documentación técnica y operativa dentro del proyecto.

Actualmente parte del conocimiento está distribuido entre:

- correos
- chats
- documentos locales
- conocimiento individual

## Problema

Cuando el conocimiento no está documentado:

- se pierde información
- aumenta dependencia de personas
- cuesta incorporar nuevos miembros
- se repiten errores
- troubleshooting tarda más

## Parte 1 - Abrir Wiki

Ingresar al proyecto de Azure DevOps.

Ir a:

Overview
? Wiki

## Parte 2 - Crear Wiki

Crear o revisar una Project Wiki.

## Parte 3 - Crear una página

Ejemplo:

Application Architecture

Agregar contenido utilizando Markdown.

## Parte 4 - Crear estructura

Ejemplo:

Home
? Architecture
? Deployment
? Operations
? Troubleshooting

## Parte 5 - Agregar contenido

Documentar:

- arquitectura
- procesos
- comandos
- decisiones
- procedimientos
- preguntas frecuentes

## Parte 6 - Utilizar Markdown

Ejemplos:

# Título

## Sección

- Lista
- Elementos

También pueden agregarse:

- links
- tablas
- imágenes
- bloques de código

## Parte 7 - Colaboración

Explicar cómo la documentación puede evolucionar junto con el proyecto.

## Parte 8 - Buenas prácticas

La documentación debería ser:

- clara
- actualizada
- accesible
- versionada
- útil para operación

## Validación

Al finalizar, el alumno debe poder explicar:

- qué es Azure Project Wiki
- qué tipo de contenido documentar
- por qué compartir conocimiento
- cómo Markdown facilita documentación
- cómo una Wiki ayuda a DevOps

## Preguntas de cierre

1. ¿Qué ocurre cuando solo una persona conoce un procedimiento crítico?
2. ¿Qué información conviene documentar en una Wiki?
3. ¿Por qué mantener documentación cerca del proyecto?
4. ¿Cómo mejora la Wiki el trabajo del equipo?

## Mensaje clave

El conocimiento también es un activo del proyecto.

Debe ser:

- compartido
- accesible
- actualizado
- reutilizable
